# Agent Handoff, Phase 1 (Domain and Consent)

Branch `feat/phase-1-domain-consent`. Code complete and verified locally against the **deployed** `ChaukannaStack` in `ap-south-1`. The Phase 1 gate (on the Amplify URL) waits only on the console steps at the bottom, which need the account owner.

## What exists

### Infrastructure (`infra/lib/chaukanna-stack.ts`, deployed)
- DynamoDB `chaukanna` + GSI1, S3 artifacts bucket (TLS enforced, lifecycle rules), Cognito pool.
- Cognito **newer managed login** plus a `ManagedLoginBranding` (without it the login page is empty). Public PKCE client. Domain prefix is `chaukanna-<stack uuid head>`, so no account id appears in login URLs.
- Callback URLs: `http://localhost:3000/api/auth/callback` always, plus `<appUrl>/api/auth/callback` from the CDK context key `chaukanna:appUrl` (set it in `infra/cdk.json` once the Amplify URL exists, then redeploy).
- Secrets Manager `chaukanna/invite-signing-key`, generated by AWS. Never in the repo.
- `chaukanna-amplify-compute-role`, **defined in CDK** (the user approved this over the manual console step). Scoped to the table, `consent/*` objects and the secret. `infra/test` fails on any wildcard action.
- Outputs go to `infra/cdk-outputs.json` (gitignored). Deploy: `cd infra && AWS_PROFILE=chaukanna npx cdk deploy ChaukannaStack --outputs-file cdk-outputs.json`.

### Web (`apps/web`)
- `src/lib/`: all business logic, unit tested with vitest (`npm test`, 58 tests).
  - `auth.ts` verifies Cognito ID tokens with `node:crypto` against the JWKS. No auth library. `auth-flow.ts` handles the code exchange.
  - `invite.ts` signed tokens `{m,h,exp}`, 72 h, with sha256 stored on the member row. `learner-session.ts` is the learner cookie; its key is derived separately from the invite key.
  - `db/` holds every DynamoDB call, with zod models. `access.ts` is the Phase 1 default-deny access rule (Phase 6 replaces it with Verified Permissions).
  - `consent.ts`: presigned upload key `consent/<memberId>/<iso>.<webm|mp4|ogg>`. The iso becomes the consent row's sort key, so replays are no-ops.
  - `i18n.ts`: every learner-facing string, in `hi` and `en`.
- Routes: every route from PRD section 11 that Phase 1 needs, plus two extra sub-routes, `POST /api/members/[id]/consent/upload-url` and `POST /api/members/[id]/invite` (fresh link after 72 h).
- Screens: `/join/[token]` (consent), `/me`, `/me/window`, `/me/consent` (learner); `/app`, `/app/invite`, `/app/members/[id]/window` (guardian).

## Decisions worth knowing
- One household per guardian. Its id is `sha256("household:"+sub)[:20]`, which makes create idempotent.
- The invite accept is single use, with a 10 minute double tap window (`ACCEPT_GRACE_SECONDS`).
- The "stop all" button on `/join` accepts the invite first, then pauses, which binds the pause to the right member.
- Re-enabling after a pause is a **fresh recorded consent**, never a toggle.
- If the mic prompt is ignored for 12 s, the screen falls back to typed "हाँ". The consent row stores `method`.
- `amplify.yml` writes non-secret env vars to `.env.production` (Amplify SSR does not pass console vars to runtime) and fails the build if one is missing. `AWS_REGION` comes from the runtime.

## Verified
Health route, 401 unauthenticated, 403 cross-origin, 410 on a bad or tampered invite, the full learner flow in a phone viewport (Hindi consent, typed fallback, window picker, kill switch, English switch), the voice consent path through presigned S3 PUT and HeadObject, idempotent replay, every row correct in DynamoDB, and log lines that carry ids only.

Not verified: the guardian screens behind Cognito (they need a real sign-up), and anything on Amplify.

## To pass the gate (account owner)
1. Push the branch (the PAT needs `workflow` scope, because the branch history contains the workflow files), then merge to `main`.
2. Amplify console, `ap-south-1`: new app from GitHub, `main`, monorepo root `apps/web`. Service role: let Amplify create it, or `chaukanna-amplify-service-role`. **Compute role: `chaukanna-amplify-compute-role`.**
3. Amplify env vars from `infra/cdk-outputs.json`: `TABLE_NAME, ARTIFACTS_BUCKET, USER_POOL_ID, USER_POOL_CLIENT_ID, COGNITO_DOMAIN, VOICE_REGION, APP_URL` (the Amplify URL). Do not add `AWS_REGION`.
4. Put the Amplify URL in `infra/cdk.json` context `"chaukanna:appUrl"`, then redeploy the stack for the callback URLs.
5. On a real phone: sign up, create household, invite, open the link, consent by voice, set a window. Check rows with the query in `docs/phases/PHASE_1_DOMAIN_AND_CONSENT.md`.
